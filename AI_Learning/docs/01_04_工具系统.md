## 一、工具基础架构 (`src/Tool.ts`)

### Tool 类型定义
每个工具实现以下接口：

```typescript
interface Tool {
  name: string                          // 工具名称 (e.g., "Read", "Bash")
  description: string                   // 描述
  inputSchema: ToolInputJSONSchema       // Zod/JSON Schema 参数定义
  prompt?: string                       // 附加到 system prompt 的说明
  isEnabled?: () => boolean             // 是否启用
  execute(toolUseId, input, context): Promise<ToolResult>
  needsPermissions?: boolean            // 是否需要权限检查
  isReadOnly?: boolean                  // 是否只读
  maxResultSizeChars?: number           // 结果大小限制
}
```

### ToolUseContext
工具执行时注入的上下文：
```typescript
{
  options: {
    tools, mainLoopModel, thinkingConfig,
    isNonInteractiveSession, agentDefinitions,
    appendSystemPrompt, forkContextMessages,
  },
  messages,                      // 对话历史
  readFileState,                 // 文件缓存
  abortController,               // 中断控制器
  getAppState/setAppState,       // 状态访问
  toolPermissionContext,         // 权限上下文
  queryTracking,                 // 查询链追踪
  agentId,                       // Agent ID (sub-agent 场景)
}
```

### 权限结果 (PermissionResult)
```
'allow'         → 直接放行
'deny'          → 拒绝
'ask'           → 弹出对话框询问用户
'allowAndSave'  → 允许并保存到 settings
'denyAndSave'   → 拒绝并保存
```

## 四、工具编排 (`src/services/tools/toolOrchestration.ts`)

### `runTools()` 函数
在 query loop 中，assistant 返回 `tool_use` blocks 后调用：

```
1. 遍历所有 tool_use blocks
2. 为每个 tool_use 执行：
   ├─ 查找工具定义 (findToolByName)
   ├─ 权限检查 (canUseTool)
   │   ├─ allow → 执行
   │   ├─ deny → 返回拒绝消息
   │   └─ ask → 弹出权限对话框 (交互模式)
   ├─ 执行工具 (tool.execute)
   ├─ 结果归一化 (normalizeMessage)
   └─ post-sampling hooks
3. 返回 tool_results 列表
4. 注入为后续 user message
```

### StreamingToolExecutor (`src/services/tools/StreamingToolExecutor.ts`)
- **功能**：在模型仍在流式生成时就开始执行工具
- **优势**：减少端到端延迟，特别是慢工具 (如长时间 Bash 命令)
- **启用条件**：`EXPERIMENTAL_STREAMING_TOOL_EXECUTION` feature flag

## 五、权限系统

### 权限模式 (`src/utils/permissions/PermissionMode.js`)
```
'default'     → 默认模式，首次使用工具时询问
'acceptEdits' → 自动接受编辑，其余询问
'plan'        → 只读模式，不允许修改
'bypass'      → 绕过所有权限检查
```

### 权限检查流程
```
canUseTool(tool, input, context, assistantMessage, toolUseID)
  ├─ bypass 模式 → allow
  ├─ 规则已保存 → 按规则决定 (allow/deny)
  ├─ isReadOnly → 允许 (不需要权限)
  └─ 否则 → ask (弹出对话框)
```

### 权限持久化
- 用户选择 `allowAndSave` / `denyAndSave` → 写入 settings.json
- 下次相同工具/模式自动应用

## 六、工具与 System Prompt

每个工具的 `prompt` 字段会被注入到 system prompt 中，告诉模型如何使用该工具。关键工具在 system prompt 中的描述包括参数说明、使用场景和限制条件。

## 七、工具结果管理

### 大小限制 (`maxResultSizeChars`)
- 每个工具可配置最大结果字符数
- 超过限制自动截断
- `toolResultStorage.ts` 管理长期存储

### 内容替换 (`ContentReplacementState`)
- 对超大工具结果，存储到磁盘
- 在消息中只保留引用，减少上下文占用
