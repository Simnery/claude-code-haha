# 03_02 — 向量数据库入门

---

## 一、什么是向量数据库？

### 一句话定义

> 专门存储和检索**向量**（数字数组）的数据库，核心能力是**相似度搜索**。

### 和传统数据库的区别

| | 传统数据库 (MySQL/PostgreSQL) | 向量数据库 (Chroma/Qdrant) |
|---|---|---|
| **存储内容** | 数字、字符串、日期 | 高维向量（如 1536 维浮点数组） |
| **查询方式** | `WHERE name = '张三'` 精确匹配 | 找最相似的 K 个向量 |
| **典型场景** | 订单、用户、库存 | 语义搜索、图片相似度、推荐系统 |
| **索引结构** | B-Tree / Hash | HNSW / IVF_FLAT (近似最近邻) |

---

## 二、核心概念

### 2.1 向量 (Vector)

```
文本 "今天天气真好"
  ↓ Embedding 模型转换
[0.12, -0.34, 0.78, 0.05, ..., -0.21]  ← 1536 个浮点数
```

每个维度代表一个"语义特征"——但具体是什么特征，人类无法解释（这是神经网络的"黑盒"特性）。

### 2.2 相似度搜索

```
query_vector = embed("如何配置数据库")  → [0.1, 0.3, ...]

向量DB中有:
  doc1: "PostgreSQL 连接配置"   → [0.09, 0.31, ...]  相似度 0.95 ← 最相关
  doc2: "Redis 缓存设置"        → [0.08, 0.28, ...]  相似度 0.87
  doc3: "前端路由配置"          → [-0.5, -0.2, ...]  相似度 0.12
```

### 2.3 索引算法

| 算法 | 特点 | 适用 |
|------|------|------|
| **HNSW** | 基于图的索引，速度快，内存消耗大 | 生产环境首选 |
| **IVF_FLAT** | 先聚类再搜索，内存省 | 百万级以上数据 |
| **暴力搜索** | 逐条计算相似度，100% 精确但极慢 | 数据量 < 1000 时可用 |

## 三、主流向量数据库对比

| 数据库 | 部署方式 | 特点 | 适用 |
|--------|---------|------|------|
| **Chroma** | 嵌入式/Server | 最简单、Python 原生、开源 | 原型/小规模 |
| **Qdrant** | Server/Docker/Cloud | 性能好、Rust 编写、过滤强 | 生产级 |
| **Pinecone** | Cloud Only | 全托管、零运维 | 不想自运维 |
| **Weaviate** | Server/Cloud | GraphQL API、内置向量化 | 企业级 |
| **Milvus** | Server/Docker | 分布式、十亿级 | 超大规模 |
| **pgvector** | PostgreSQL 扩展 | 和业务数据库一体 | 已有 PG 的项目 |
| **FAISS** (Meta) | 库 (不是DB) | 纯内存、极致速度 | 研究/嵌入式 |
| **Elasticsearch** | Server | 全文搜索 + 向量搜索混合 | 已有 ES 的项目 |

## 四、Chroma 快速上手

### 安装

```bash
pip install chromadb
```

### 基础用法

```python
import chromadb

# 1. 创建客户端（内存模式）
client = chromadb.Client()

# 2. 创建集合（类似 SQL 的 table）
collection = client.create_collection(name="my_docs")

# 3. 添加文档
collection.add(
    documents=[
        "PostgreSQL 数据库连接配置指南",
        "React 前端路由使用文档",
        "Redis 缓存策略最佳实践",
    ],
    ids=["doc1", "doc2", "doc3"]
)

# 4. 查询（自动向量化 + 检索）
results = collection.query(
    query_texts=["如何连接数据库"],
    n_results=2
)

print(results['documents'])
# [['PostgreSQL 数据库连接配置指南', 'Redis 缓存策略最佳实践']]
```

### 持久化模式

```python
# 数据存到磁盘，重启不丢失
client = chromadb.PersistentClient(path="./chroma_data")
```

## 五、pgvector — PostgreSQL 扩展

### 为什么选 pgvector？

- 如果项目已经用 PostgreSQL，不需要引入新数据库
- 向量和业务数据可以在同一个查询中 JOIN
- 运维团队熟悉 PG

### 基础用法

```sql
-- 1. 启用扩展
CREATE EXTENSION vector;

-- 2. 创建带向量字段的表
CREATE TABLE documents (
    id SERIAL PRIMARY KEY,
    content TEXT,
    embedding vector(1536)  -- 1536 维向量
);

-- 3. 插入数据（向量由应用代码生成）
INSERT INTO documents (content, embedding)
VALUES ('数据库配置说明', '[0.1, 0.2, ...]');

-- 4. 相似度搜索
SELECT content, 1 - (embedding <=> '[0.09, 0.21, ...]') AS similarity
FROM documents
ORDER BY embedding <=> '[0.09, 0.21, ...]'
LIMIT 5;
-- <=> 是余弦距离运算符
```

## 六、生产环境选型决策树

```
你的情况是什么？
  ├─ 刚学，想快速实验
  │   → Chroma (嵌入式模式，3 行代码跑起来)
  │
  ├─ 个人项目，数据 < 10 万条
  │   → Chroma (持久化模式) 或 pgvector
  │
  ├─ 小团队产品，数据 10 万 ~ 100 万
  │   → Qdrant (性能好，过滤强) 或 Pinecone (不想管运维)
  │
  ├─ 企业级，已有 PostgreSQL
  │   → pgvector (统一运维，JOIN 方便)
  │
  ├─ 超大规模，亿级以上
  │   → Milvus (分布式) 或 Pinecone
  │
  └─ 需要混合搜索 (全文 + 向量)
      → Elasticsearch 或 Weaviate
```

## 七、常见问题

### Q: 向量数据库和普通数据库能一起用吗？

能，而且推荐。业务数据存 PG，向量数据存 Qdrant，通过 doc_id 关联。

### Q: 需要自己写向量化代码吗？

Chroma 和 Weaviate 支持自动向量化（传入文本，内部调 Embedding API）。但生产环境通常自己控制向量化过程（重试/批处理/缓存）。

### Q: 多久需要重新生成向量？

换了 Embedding 模型时需要全部重建。文档内容更新时增量重建即可。
