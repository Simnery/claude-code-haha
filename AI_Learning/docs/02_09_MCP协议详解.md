# 02_09 — MCP 协议详解

> Model Context Protocol — Anthropic 提出的 Agent 与外部工具/数据源通信的标准协议。

---

## 一、MCP 解决什么问题？

### 问题：M×N 连接爆炸

```
没有标准协议时，每个 Agent 要对接每个工具都要写一套代码：

        Agent A    Agent B    Agent C
          │  │  │    │  │  │    │  │  │
          ▼  ▼  ▼    ▼  ▼  ▼    ▼  ▼  ▼
         DB  API  FS  DB  API  FS  DB  API  FS

N 个 Agent × M 个工具 = N×M 套对接代码
```

### 解决：标准协议

```
有了 MCP 之后：

        Agent A    Agent B    Agent C
          │          │          │
          └──────────┼──────────┘
                     │
              MCP 协议 (统一标准)
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
       MCP Server  MCP Server  MCP Server
       (数据库)    (API)       (文件系统)

N 个 Agent + M 个工具 = N+M 套对接（每个工具只需写一次 MCP Server）
```

## 二、MCP 架构

### 三大角色

```
┌─────────────┐         ┌─────────────┐
│  MCP Host    │ ←──→   │ MCP Client  │
│ (Claude Code │         │ (协议客户端) │
│  / 桌面端等)  │         └──────┬──────┘
└─────────────┘                │
       │                  JSON-RPC 2.0
       │                over stdio / SSE / Streamable
       ▼                       │
┌─────────────┐         ┌──────▼──────┐
│ MCP Server  │ ←──→   │ MCP Server  │
│ (工具提供方) │         │ (工具提供方) │
└─────────────┘         └─────────────┘
```

| 角色 | 说明 | 示例 |
|------|------|------|
| **MCP Host** | 运行 Agent 的应用 | Claude Code、Cursor、VS Code |
| **MCP Client** | 协议客户端，Host 内嵌 | 每个 MCP Server 有一个对应的 Client 连接 |
| **MCP Server** | 提供工具/资源/提示词的服务 | GitHub Server、Filesystem Server、数据库 Server |

### 通信方式

| 传输方式 | 说明 | 适用 |
|---------|------|------|
| **stdio** | 标准输入输出，启动子进程 | 本地工具（最常用） |
| **SSE** | Server-Sent Events，HTTP 流 | 远程服务 |
| **Streamable HTTP** | 新标准 (2025)，替代 SSE | 远程服务（推荐） |

## 三、MCP Server 提供什么？

### 三大能力

```typescript
interface MCPServer {
  // 1. Tools (工具) — 可被 Agent 调用的操作
  tools: Tool[]

  // 2. Resources (资源) — 可被 Agent 读取的数据
  resources: Resource[]

  // 3. Prompts (提示词模板) — 预定义的提示词
  prompts: Prompt[]
}
```

### 3.1 Tools — 工具

```
Tool = Agent 可以执行的操作

示例:
  - github_create_issue     → 创建 GitHub Issue
  - filesystem_read_file    → 读取文件
  - database_query          → 查询数据库

每个 Tool 包含:
  - name:         工具名
  - description:  描述（给模型看，帮助判断何时使用）
  - inputSchema:  参数 JSON Schema
```

### 3.2 Resources — 资源

```
Resource = Agent 可以读取的只读数据

示例:
  - file:///project/README.md    → 文件内容
  - postgres://users/table       → 数据库表结构
  - notion://workspace/page      → Notion 页面

和 Tool 的区别:
  - Tool = 执行操作（有副作用）
  - Resource = 读取数据（只读）
```

### 3.3 Prompts — 提示词模板

```
Prompt = 预定义的提示词模板

示例:
  - "代码审查" 模板 → 帮助 Agent 规范化代码审查
  - "SQL 优化" 模板 → 帮助 Agent 写出更好的 SQL

Agent 可以调用这些模板来获得结构化的指令。
```

## 四、MCP 通信流程

### 生命周期

```
1. Host 启动 MCP Server (子进程 / 连接远程)
      ↓
2. Client 发送 initialize 请求
      ↓
3. Server 回复能力列表 (tools/resources/prompts)
      ↓
4. Agent 正常工作中...
      │
      ├─ Agent 想调工具 → Client 发 tools/call
      ├─ Agent 想读资源 → Client 发 resources/read
      └─ Agent 想取提示 → Client 发 prompts/get
      ↓
5. 连接关闭 → Server 退出
```

### JSON-RPC 消息示例

```json
// Agent 调用 GitHub 创建 Issue
// → Client 发送:
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "github_create_issue",
    "arguments": {
      "owner": "my-org",
      "repo": "my-project",
      "title": "修复登录页样式 bug",
      "body": "在 Safari 浏览器下登录按钮错位"
    }
  }
}

// ← Server 返回:
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "Issue #1234 已创建: https://github.com/my-org/my-project/issues/1234"
      }
    ]
  }
}
```

## 五、MCP Server 开发实战

### 最简 MCP Server (TypeScript)

```typescript
// server.ts — 一个最简单的 MCP Server
import { McpServer } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

// 1. 创建 Server
const server = new McpServer({
  name: "my-first-server",
  version: "1.0.0",
});

// 2. 注册 Tool
server.tool(
  "hello",                          // 工具名
  "向指定的人说你好",                 // 描述
  {                                 // 参数 Schema
    name: {
      type: "string",
      description: "对方的名字"
    }
  },
  async ({ name }) => ({           // 执行函数
    content: [{ type: "text", text: `你好，${name}！` }]
  })
);

// 3. 启动（stdio 模式）
const transport = new StdioServerTransport();
await server.connect(transport);

// 配置文件 .claude/.mcp.json:
// {
//   "mcpServers": {
//     "hello-server": {
//       "command": "bun",
//       "args": ["run", "server.ts"]
//     }
//   }
// }
```

### 更实用的例子：天气查询 MCP Server

```typescript
server.tool(
  "get_weather",
  "查询指定城市的天气",
  {
    city: { type: "string", description: "城市名，如 '北京'" }
  },
  async ({ city }) => {
    // 实际项目中调天气 API
    const weather = await fetchWeatherAPI(city)
    return {
      content: [{
        type: "text",
        text: `${city}今天${weather.condition}，温度${weather.temp}°C`
      }]
    }
  }
)

// 注册 Resource (让 Agent 能读取城市列表)
server.resource(
  "cities://list",
  "支持的城市列表",
  async () => ({
    contents: [{
      uri: "cities://list",
      text: JSON.stringify(["北京", "上海", "深圳", "杭州"])
    }]
  })
)
```

### MCP Server 的配置 (claude_code)

```json
// ~/.claude/.mcp.json 或 项目 .claude/.mcp.json
{
  "mcpServers": {
    // 本地 stdio 方式
    "filesystem": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/workspace"]
    },
    // 远程 SSE 方式
    "github": {
      "type": "sse",
      "url": "https://mcp.github.com/sse",
      "headers": {
        "Authorization": "Bearer github_pat_xxx"
      }
    }
  }
}
```

## 六、MCP vs Function Calling

| | MCP | Function Calling |
|---|---|---|
| **提出者** | Anthropic | OpenAI |
| **范围** | 完整的协议规范 | API 的一个功能 |
| **工具定义** | Server 端定义 | 调用时传入 tools 参数 |
| **工具发现** | 自动 (Server 声明) | 手动 (开发者代码中定义) |
| **资源/提示词** | ✅ 支持 | ❌ 不支持 |
| **传输** | stdio / SSE / Streamable | HTTP (API 请求中) |
| **生态** | 快速增长，社区贡献 | OpenAI 生态 |
| **跨模型** | 是 (不绑定模型) | 是 (OpenAI API 格式被广泛借用) |

> **简单理解**: MCP = 工具的标准"插座"，Function Calling = 工具的一种"调用方式"。两者不矛盾——MCP 的 Server 可以被 Claude/GPT/任何模型通过各自的 Tool Use 机制调用。

## 八、MCP 的局限与未来

### 当前局限

| 问题 | 说明 |
|------|------|
| **认证不统一** | 每个 Server 自己处理认证，没有统一方案 |
| **服务发现** | 没有中心化的 MCP Server 注册表 |
| **流式工具结果** | 标准支持但生态不成熟 |
| **版本管理** | Server 版本升级可能导致不兼容 |
| **安全审计** | 第三方 Server 的安全审查靠人工 |

### 发展趋势

- **MCP 2.0**: Streamable HTTP 替代 SSE，性能更好
- **服务注册表**: Anthropic 正在建官方 MCP Server 市场
- **A2A + MCP**: Google 的 A2A (Agent-to-Agent) 和 MCP 互补
- **企业级**: Microsoft/governance、OAuch 集成
