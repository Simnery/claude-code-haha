# 03_08 — 模型推理部署

> 从"调用 API"到"自部署模型"，需要了解推理引擎、量化、GPU 管理等。

---

## 一、为什么需要自部署？

| 场景 | 方案 |
|------|------|
| 日调用 < 1000 次 | API 即可 |
| 日调用 > 10000 次 | 自部署更省钱 |
| 数据必须内网 | 自部署（合规要求） |
| 需要定制模型 | 微调 + 自部署 |
| 需要低延迟 (<100ms) | 自部署（更可控） |

---

## 二、推理引擎对比

| 引擎 | 特点 | 适用 |
|------|------|------|
| **vLLM** | 性能最强、PagedAttention、连续批处理 | 生产环境首选 |
| **Ollama** | 最简单、一行命令、自动下载模型 | 本地开发/测试 |
| **TGI** (HuggingFace) | 企业级、支持多模型、HuggingFace 生态 | HuggingFace 用户 |
| **llama.cpp** | CPU 推理、量化、支持任何硬件 | 无 GPU 环境 |
| **Triton Inference Server** | NVIDIA 官方、多框架支持 | 超大规模 |

## 三、Ollama — 最快上手

```bash
# 安装
curl -fsSL https://ollama.com/install.sh | sh

# 运行模型
ollama run qwen2.5:7b         # 7B 模型
ollama run llama3.1:8b        # 8B 模型
ollama run deepseek-r1:14b    # 14B 模型

# API 调用（和 OpenAI 兼容）
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen2.5:7b",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

**硬件要求**:

| 模型规模 | 原始大小 (FP16) | 4bit 量化 (Q4_K_M) | 8bit 量化 | 推荐 GPU | 纯 CPU 内存 |
|---------|----------------|-------------------|----------|---------|------------|
| 1B-3B | 2-6 GB | 1-2 GB | 1.5-3 GB | 无需 GPU | 4 GB |
| 7B-8B | 14-16 GB | 4-5 GB | 7-8 GB | RTX 3060(12G) / M1 16G | 8 GB |
| 13B-14B | 26-28 GB | 7-9 GB | 13-15 GB | RTX 4070(12G) / RTX 3080 | 16 GB |
| 30B-34B | 60-68 GB | 17-20 GB | 30-35 GB | RTX 4090(24G) / A5000 | 32 GB |
| 70B-72B | 140-144 GB | 35-42 GB | 70-75 GB | A100(80G) / 2×RTX 4090 | 64 GB |
| 110B+ | 220+ GB | 55-70 GB | 110+ GB | 2×A100 / 4×RTX 4090 | 128 GB+ |
| 405B | 810 GB | 200-230 GB | — | 4×A100(80G) / 8×H100 | 不推荐 |

**量化格式对比**：

| 格式 | 质量损失 | 显存节省 | 适用场景 |
|------|---------|---------|---------|
| FP16 (无量化) | 无 | 0% | 微调、最高质量推理 |
| 8-bit (INT8) | 极小 (<0.5%) | ~50% | 有充足 GPU 的生产环境 |
| 4-bit (Q4_K_M) | 小 (1-3%) | ~75% | **最常用**，性价比最高 |
| 3-bit (Q3_K_M) | 中等 (3-8%) | ~81% | 显存极度紧张时 |
| 2-bit (Q2_K) | 大 (8-20%) | ~87% | 仅限实验，不推荐生产 |

| 级别 | 配置 | 可支撑并发 | 月成本(云/租用) | 适用规模 |
|------|------|-----------|---------------|---------|

## 四、vLLM — 生产部署

```bash
# 安装
pip install vllm

# 启动 OpenAI 兼容 API 服务
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --host 0.0.0.0 \
  --port 8000 \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.9

# 调用
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen2.5-7B-Instruct",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

### vLLM 核心参数

| 参数 | 说明 | 建议值 |
|------|------|--------|
| `--max-model-len` | 最大上下文长度 | 按需 (4096/8192/32768) |
| `--gpu-memory-utilization` | GPU 显存使用率 | 0.85-0.95 |
| `--tensor-parallel-size` | 多 GPU 并行 | GPU 数量 |
| `--dtype` | 推理精度 | auto (自动检测) |

## 五、量化 — 降低部署成本

### 什么是量化？

把模型参数从 16-bit 浮点数压缩到 4-bit 整数，**几乎不损失效果，显存降到 1/4**。

```
模型: Qwen2.5-7B
原始大小 (FP16): ~14GB
4-bit 量化 (GGUF): ~4GB  ← 消费级 GPU 能跑
```

### 量化格式

| 格式 | 精度 | 大小 | 用途 |
|------|------|------|------|
| GGUF (Q4_K_M) | 4-bit | 最小 | llama.cpp / Ollama |
| GPTQ | 4-bit | 小 | GPU 推理 |
| AWQ | 4-bit | 小 | GPU 推理（比 GPTQ 略好） |
| FP16 | 16-bit | 大 | 微调基线 |

### 获取量化模型

```bash
# HuggingFace 上有现成的量化版
# 搜 "Qwen2.5-7B-Instruct-GGUF" 或 "Qwen2.5-7B-Instruct-AWQ"

# 或用 Ollama 自动下载（内置量化版）
ollama run qwen2.5:7b  # 自动下载 Q4_K_M 量化版
```

## 六、部署架构

### 最小化单机部署

```
┌─────────────────────────────────┐
│          服务器 (单 GPU)          │
│  ┌───────────────────────────┐  │
│  │  vLLM / Ollama             │  │
│  │  :8000 (OpenAI 兼容 API)   │  │
│  └───────────────────────────┘  │
│              ↑                   │
│  ┌───────────────────────────┐  │
│  │  Agent 应用                 │  │
│  │  (Node.js / Python)        │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

### 生产级多模型架构

```
┌─────────────┐
│  LiteLLM     │ ← 统一网关，路由请求到不同模型
│  :4000       │
└──┬──┬──┬────┘
   │  │  │
   ▼  ▼  ▼
┌──────┐ ┌──────┐ ┌──────┐
│vLLM  │ │vLLM  │ │Ollama│
│GPT-4o│ │Claude│ │本地  │
│等效  │ │等效  │ │小模型│
└──────┘ └──────┘ └──────┘

LiteLLM 配置示例（本项目用的就是这个）:
  - 简单任务 → 本地小模型 (便宜)
  - 复杂任务 → 云端大模型 (强)
  - 敏感数据 → 内网部署模型 (安全)
```

## 七、关键认知

1. **API 起步，按需自部署** — 不要一上来就自己部署模型
2. **先用 Ollama 理解部署** — 然后再上 vLLM 做生产优化
3. **量化是标配** — 不做量化，7B 模型要 14GB 显存，做量化只要 4GB
4. **LiteLLM 做统一网关** — 混合使用多个模型/API/自部署的推荐方案
