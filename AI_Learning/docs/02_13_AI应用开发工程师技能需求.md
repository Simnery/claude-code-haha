## 二、Agent/RAG 应用开发（最大需求）

### 日常工作内容

```
60% — 写 Agent 业务逻辑
  ├─ 设计 Agent Loop（规划→执行→观察→修正）
  ├─ 定义 Tool 接口（调 API / 查数据库 / 改文件）
  ├─ 写 System Prompt（反复调试直到行为正确）
  ├─ 搭建 RAG 流水线（文档切分→向量化→检索→注入）
  └─ 集成 MCP / Function Calling 工具

20% — 效果优化
  ├─ 调整 Prompt 提升任务完成率
  ├─ 优化检索精度（Embedding 选型、Chunk 策略）
  ├─ 加记忆系统（短期+长期）
  └─ A/B 测试不同模型和策略

10% — 工程化
  ├─ 加权限控制
  ├─ 加监控/日志/成本追踪
  └─ 性能优化（并发、缓存、流式）

10% — 产品对接
  ├─ 和产品经理一起定义 Agent 行为边界
  └─ 收用户反馈，迭代 Prompt
```

## 九、12-Factor Agents 方法论 (Anthropic 系工程标准)

> 来源：humanlayer/12-factor-agents + Anthropic "Building Effective Agents" 官方指南

这是目前最受认可的 **Agent 工程化标准**，相当于传统软件开发的 12-Factor App：

| Factor | 核心原则 | 对应技术要求 |
|--------|---------|-------------|
| 1 | **自然语言即代码** | Prompt Engineering 是核心开发活动 |
| 2 | **拥有你的 Prompt** | Prompt 版本管理（Git）、A/B 测试、评估体系 |
| 3 | **拥有你的上下文窗口** | Context Engineering — 主动管理而非被动填充 |
| 4 | **工具就是结构化输出** | Function Calling / JSON Mode / BAML Schema-Aligned Parsing |
| 5 | **统一执行环境** | Docker 沙箱、确定性工具结果 |
| 6 | **紧循环 + 短反馈** | Agent Loop 中快速失败、快速修正 |
| 7 | **用工具调用接触人类** | Human-in-the-Loop 通过 Tool 实现，不阻塞 Agent 循环 |
| 8 | **可观测性一等公民** | 每步决策可追溯、可回放、可调试 |
| 9 | **无状态 Agent** | Redux 模式 — Agent 是 stateless reducer |
| 10 | **小规模、聚焦的 Agent** | 多小 Agent > 一个大 Agent |
| 11 | **从简单架构开始** | 先用确定性代码 + LLM 点缀，再考虑框架 |
| 12 | **持续评估** | 自动化回归测试 Agent 行为 |

**暴露的技能缺口**：
- 之前遗漏了 **Prompt 版本管理/评估体系** — 这是 Agent 工程化的核心
- 之前遗漏了 **Agent 可观测性** — 调试/回放/追踪
- 之前遗漏了 **BAML/DSL** — Schema-Aligned Parsing 等结构化输出方案

## 十一、AI 评估与评测 (Evals)

> 来源：行业实践、Anthropic/OpenAI 工程博客

这是 JD 里很少提但实际工作中占比很大的领域：

### 为什么重要？
Agent 的行为不是"对/错"二元判断，而是"好不好"——这需要评估体系。

### 评估维度

| 维度 | 评估方法 | 工具 |
|------|---------|------|
| **任务完成率** | 给定 N 个标准任务，统计 Agent 成功率 | 自建测试集 |
| **工具选择准确率** | Agent 是否正确选择了工具 | 日志分析 + 人工审核 |
| **输出质量** | LLM-as-Judge（用另一个模型打分） | LangSmith / Braintrust |
| **响应时间** | 首 token 延迟、任务总耗时 | 遥测系统 |
| **安全性** | 越狱测试、危险指令拒绝率 | 红队测试 |
| **一致性** | 相同输入多次执行，结果是否一致 | 重复测试 |

### 评估工具

| 工具 | 用途 |
|------|------|
| **LangSmith** (LangChain) | Agent 链路追踪 + 评估 |
| **Braintrust** | 提示词实验 + 评估 |
| **Arize Phoenix** | LLM 可观测性 + 评估 |
| **Weights & Biases** | 模型训练/微调评估 |
| **Ragas** | RAG 系统专用评估 |
| **DeepEval** | 开源 LLM 评估框架 |

## 十二、安全与 Guardrails

> 来源：Microsoft Agent Governance、OWASP Agent Top 10、行业实践

### OWASP Agent Top 10 (2025-2026)

| # | 风险 | 说明 |
|---|------|------|
| 1 | 权限过度 | Agent 拿到不该有的系统权限 |
| 2 | 提示注入 | 用户输入劫持 Agent 行为 |
| 3 | 工具滥用 | Agent 以危险方式调用工具（如 `rm -rf /`） |
| 4 | 数据泄露 | Agent 把敏感信息发到外部 |
| 5 | 供应链攻击 | MCP Server / Plugin 带恶意代码 |
| 6 | 输出不可信 | Agent 生成的内容未经验证直接使用 |
| 7 | 状态污染 | 长期记忆被恶意修改 |
| 8 | 拒绝服务 | Agent 死循环消耗资源 |
| 9 | 越权操作 | Agent 以高权限身份执行低权限用户的操作 |
| 10 | 审计缺失 | 无法追溯谁让 Agent 做了什么 |

### Guardrails 工具

| 工具 | 用途 |
|------|------|
| **Guardrails AI** | 开源 Guard 框架，输入/输出校验 |
| **NVIDIA NeMo Guardrails** | 对话安全护栏 |
| **Microsoft Agent Governance Toolkit** | 企业级 Agent 治理（最新开源） |
| **Lakera Guard** | 提示注入检测 |
| **Claude Content Filters** | Anthropic 原生安全过滤 |
