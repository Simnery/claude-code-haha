## 一、最简单的方法：console.log

### 用法

```typescript
// 最基础
console.log("执行到这里了")
console.log("变量值：", someVariable)

// 打印对象（自动展开）
console.log("当前状态：", JSON.stringify(state, null, 2))

// 打印类型
console.log("类型：", typeof value)
console.log("是数组吗：", Array.isArray(value))
```

### 本项目注意

本项目内部有专门的日志模块，生产环境 console.log 可能被抑制。内部代码用：

```typescript
import { logForDebugging } from './utils/debug.js'
import { logError } from './utils/log.js'

logForDebugging('debug', '关键信息', { extra: 'data' })
```

## 二、Bun 调试器

### 方式 1：Bun --inspect（推荐）

```bash
# 启动时带上 --inspect 参数
bun --inspect ./src/entrypoints/cli.tsx

# 或指定端口
bun --inspect=9229 ./src/entrypoints/cli.tsx
```

然后在浏览器打开 `chrome://inspect` 或 VS Code 中 attach。

### 方式 2：代码中加 debugger

```typescript
// 在可疑位置插入 debugger 语句
async function* queryLoop(params: QueryParams) {
  while (true) {
    debugger   // ← 运行到这里会暂停，可以检查所有变量
    // ...
  }
}
```

```bash
bun --inspect ./src/entrypoints/cli.tsx
# 运行到 debugger 语句时会自动暂停
```

### 方式 3：VS Code 断点调试

在项目根目录打开 VS Code，在任意 `.ts` 文件中点击行号左侧设置断点，然后 `F5` 启动调试。

配置文件 `.vscode/launch.json`：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "bun",
      "request": "launch",
      "name": "Debug CLI",
      "program": "${workspaceFolder}/src/entrypoints/cli.tsx",
      "args": [],
      "cwd": "${workspaceFolder}"
    }
  ]
}
```

## 四、追踪代码执行流

### 方法 1：打调用栈

```typescript
// 想知道是谁调用了当前函数
console.log(new Error().stack)

// 输出类似：
//   at queryLoop (src/query.ts:243)
//   at query (src/query.ts:221)
//   at submitMessage (src/QueryEngine.ts:211)
```

### 方法 2：Monkey-patch 关键函数

```typescript
// 在 init.ts 或 main.tsx 开头临时加入
const originalCallModel = deps.callModel
deps.callModel = async (params: any) => {
  console.log('API 调用参数:', {
    model: params.options.model,
    messageCount: params.messages.length,
    toolCount: params.tools.length,
  })
  const result = await originalCallModel(params)
  console.log('API 调用完成')
  return result
}
```

### 方法 3：grep 追踪变量来源

```bash
# 想知道某个变量从哪里来
grep -rn "mainLoopModel" src/ | head -20

# 看某个函数的调用者
grep -rn "getMainLoopModel()" src/
```

## 五、常见问题的调试手段

### 问题 1：模型返回了意料之外的内容

```typescript
// 在 query.ts 中临时插入，查看实际发送和接收的内容
const messages = prependUserContext(messagesForQuery, userContext)
console.log('=== 发送的消息 ===')
console.log(JSON.stringify(messages.slice(-3), null, 2))  // 只看最后 3 条
console.log('=== System Prompt 长度 ===', systemPrompt.length)
```

### 问题 2：工具权限总是弹出询问

```bash
# 检查已保存的权限设置
cat ~/.claude/settings.json | grep -A5 permissions

# 或直接 bypass 测试
bun run claude --permission-mode bypass
```

### 问题 3：上下文超限

```typescript
// 在 query.ts 的 autocompact 之前插入
const tokenCount = tokenCountWithEstimation(messagesForQuery)
const contextWindow = getContextWindowForModel(mainLoopModel)
console.log(`Token: ${tokenCount} / ${contextWindow}`)
console.log(`使用率: ${Math.round(tokenCount / contextWindow * 100)}%`)
```

### 问题 4：Provider 连接失败

```bash
# 检查环境变量是否正确加载
bun run claude --dump-system-prompt

# 检查 .env 文件是否被解析
# 在 main.tsx 早期加入：
console.log('ANTHROPIC_BASE_URL:', process.env.ANTHROPIC_BASE_URL)
console.log('ANTHROPIC_MODEL:', process.env.ANTHROPIC_MODEL)
```

## 七、调试心理模型

```
1. 猜测问题可能在哪里（根据错误信息）
2. 在可疑位置加 console.log / debugger
3. 缩小范围，直到定位到具体行
4. 理解为什么会出错（对比预期行为 vs 实际行为）
5. 修复并验证
```

### 本项目调试小贴士

- **最难调试的部分**是 `query.ts` 的 while(true) 循环——因为流程可能走很多轮迭代。建议在循环开头加 `console.log("迭代", turnCount, "当前消息数", messages.length)`
- **async/await 的 try/catch 会吞掉错误**。如果发现莫名其妙的静默失败，检查 catch 块是否有 `console.error`
- **生成器被提前 close** 是常见 BUG。如果看到 `Terminal { reason: 'interrupted' }` 但没主动按 Ctrl+C，可能是上游调用了 `generator.return()`
- **Flux/Suspense/Ink 渲染**的异步生命周期复杂，UI 不更新时先确认数据是否真的变了（打 log），再怀疑渲染
