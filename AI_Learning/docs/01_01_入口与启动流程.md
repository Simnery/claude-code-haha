# 01 — 入口与启动流程

> 覆盖文件：`src/entrypoints/cli.tsx`, `src/main.tsx`, `src/entrypoints/init.ts`, `src/bootstrap/state.ts`, `src/replLauncher.tsx`

---

## 一、整体启动链路

```
claude.bat / claude.sh
  └─ bun ./src/entrypoints/cli.tsx       ← CLI 入口，fast-path 分发
       └─ import('../main.js')            ← 主命令处理器 (main.tsx)
            ├─ init()                     ← 初始化 (entrypoints/init.ts)
            ├─ Commander 命令行参数解析
            ├─ 模型 & 权限 & MCP 初始化
            └─ launchRepl()               ← 进入 REPL 交互循环 (replLauncher.tsx)
```

---

## 二、CLI 入口 (`src/entrypoints/cli.tsx`)

### 职责
在加载完整 CLI 之前做**快速路径分发**，所有 import 都是动态的，避免无关模块被加载。

### 入口函数 `main()` (L33-298)

按优先级检查 `process.argv`，命中即返回：

| 优先级 | 命令/标志 | 行为 |
|--------|----------|------|
| 1 | `--version`, `-v`, `-V` | 输出版本号，零模块加载 |
| 2 | `--dump-system-prompt` | 输出当前模型的 system prompt 后退出 (Ant-only) |
| 3 | `--claude-in-chrome-mcp` | 启动 Chrome MCP 服务器 |
| 4 | `--chrome-native-host` | 启动 Chrome Native Host |
| 5 | `--computer-use-mcp` | 启动 Computer Use MCP 服务器 |
| 6 | `--daemon-worker=<kind>` | 后台 Worker (内部) |
| 7 | `remote-control`, `rc`, `bridge` 等 | Bridge 模式，远程控制 |
| 8 | `daemon` | 启动后台守护进程 |
| 9 | `ps`, `logs`, `attach`, `kill`, `--bg`, `--background` | 会话管理 |
| 10 | `new`, `list`, `reply` | 模板任务命令 |
| 11 | `environment-runner` | 无头 BYOC Runner |
| 12 | `self-hosted-runner` | 自托管 Runner |
| 13 | `--worktree --tmux` | tmux worktree 快速路径 |
| 14 | `--update`, `--upgrade` | 重写为 `update` 子命令 |
| 15 | **其他所有参数** | 加载 `src/main.js` → 完整 CLI |

### 关键逻辑
- L281-285: `--bare` 标志提前设置 `CLAUDE_CODE_SIMPLE=1`，在 Commander 解析前生效
- L287-297: 无特殊标志时，启动 early input 捕获，动态 import `main.js`

## 三、主入口 (`src/main.tsx`)

### 文件规模
~4000+ 行，是整个项目最核心的编排文件。

### 启动前置操作 (L9-20)
```typescript
profileCheckpoint('main_tsx_entry')    // 性能打点
startMdmRawRead()                       // 并行启动 MDM 读取
startKeychainPrefetch()                // 并行预热 Keychain (macOS)
```

### Commander CLI 定义
`main()` 函数中用 `@commander-js/extra-typings` 构建命令行参数：

| 关键参数 | 说明 |
|---------|------|
| `--model <name>` | 指定模型 (sonnet/opus/haiku/具体模型ID) |
| `-p`, `--print` | 无头模式，输出后退出 |
| `--continue`, `-c` | 继续上一次会话 |
| `--resume <id>` | 恢复到指定会话 |
| `--permission-mode` | 权限模式 (default/acceptEdits/bypass/plan) |
| `--output-format` | 输出格式 (text/json/stream-json) |
| `--mcp-config` | MCP 服务器配置 |
| `--allowedTools` | 工具白名单 |
| `--disallowedTools` | 工具黑名单 |
| `--agents` | Agent 配置 JSON |
| `--system-prompt` | 自定义 system prompt |
| `--add-dir` | 添加额外目录 |

### 主流程 (action handler 内部)

```
1. handleEarlyExitOptions()         → 处理 --version, mcp 子命令等
2. 设置 isInteractive              → 交互/无头模式判断
3. handleTeleportArgs()            → 处理 teleport 恢复
4. init()                          → 完整初始化 (详见第四节)
5. 模型解析                         → getUserSpecifiedModelSetting() → parseUserSpecifiedModel()
6. 权限初始化                       → initialPermissionModeFromCLI()
7. MCP 初始化                      → getMcpToolsCommandsAndResources()
8. launchRepl()                    → 启动 REPL 交互循环
```

### 模型解析链 (L2033-2137)
```
options.model                               (--model 标志)
  ?? process.env.ANTHROPIC_MODEL            (环境变量)
  ?? getDefaultMainLoopModel()              (默认值: Opus for Max/Team, Sonnet for others)
  → parseUserSpecifiedModel()               (别名解析 → 具体模型ID)
```

## 四、初始化系统 (`src/entrypoints/init.ts`)

### `init()` 函数 (memoized，全生命周期只执行一次)

按顺序执行以下初始化步骤：

```
1. enableConfigs()                  → 读取 settings.json, .env, 合并配置
2. applySafeConfigEnvironmentVariables()  → 应用安全环境变量 (不含敏感信息)
3. applyExtraCACertsFromConfig()    → TLS 证书
4. 检测仓库 (Git root)
5. setShellIfWindows()              → Windows 下设置 shell
6. 启动 LSP Manager
7. configureGlobalAgents()          → 全局代理配置
8. configureGlobalMTLS()            → mTLS 配置
9. setupGracefulShutdown()          → 优雅关闭注册
10. initializePolicyLimitsLoadingPromise()  → 策略限制异步加载
11. initializeRemoteManagedSettingsLoadingPromise() → 远程管理设置
```

### `initializeTelemetryAfterTrust()` — 用户信任后初始化
- 初始化 OpenTelemetry (Meter, Logger, Tracer)
- 初始化 GrowthBook (功能开关)
- 首次启动时间记录

## 五、全局状态管理 (`src/bootstrap/state.ts`)

### 设计原则
**单例全局状态**，模块级 `const STATE: State = getInitialState()`，所有访问通过 getter/setter 函数。

### 核心状态分类

| 类别 | 字段 | 说明 |
|------|------|------|
| 路径 | `originalCwd`, `projectRoot`, `cwd` | 工作目录 (支持 worktree) |
| 模型 | `mainLoopModelOverride`, `initialMainLoopModel`, `modelStrings` | 模型选择状态 |
| 会话 | `sessionId`, `parentSessionId`, `sessionProjectDir` | 会话标识 (UUID) |
| 成本 | `totalCostUSD`, `totalAPIDuration`, `totalToolDuration`, `modelUsage` | API 使用统计 |
| 交互 | `isInteractive`, `isRemoteMode`, `replBridgeActive` | 运行模式标志 |
| 权限 | `sessionBypassPermissionsMode` | 会话级权限旁路 |
| 遥测 | `meter`, `sessionCounter`, `costCounter`, `tokenCounter` 等 | OpenTelemetry |
| Beta | `afkModeHeaderLatched`, `fastModeHeaderLatched`, `thinkingClearLatched` 等 | 粘性 Beta 头部 |
| 其他 | `agentColorMap`, `invokedSkills`, `slowOperations`, `registeredHooks` | 各子系统状态 |

### 关键函数
- `getSessionId()` / `regenerateSessionId()` → 会话 ID 管理
- `switchSession()` → 原子切换会话，触发 `onSessionSwitch` 信号
- `getMainLoopModelOverride()` / `setMainLoopModelOverride()` → 模型 override
- `resetStateForTests()` → 仅测试环境可用

## 六、REPL 启动 (`src/replLauncher.tsx`)

### `launchRepl()` 职责
- 组装初始消息 (system message + user message)
- 处理会话恢复 (/resume, /continue)
- 渲染 Ink React TUI
- 进入消息循环 (用户输入 → API 调用 → 工具执行 → 响应渲染 → 循环)

---

## 七、关键设计模式

1. **动态 import / 懒加载**：快速路径不加载完整模块，使用 `await import()` 按需加载
2. **feature flags**：`bun:bundle` 的 `feature()` 函数在构建时做 DCE (Dead Code Elimination)，外部构建不包含 Ant-only 代码
3. **Bootstrap 隔离**：`bootstrap/state.ts` 作为 DAG 叶子节点，只能被其他模块 import，自身不 import 任何项目模块
4. **启动性能优化**：MDM 读取、Keychain 预取等在 import 期间并行执行 (~135ms import 耗时 + 并行子进程)
