## 二、什么是 TypeScript？

### 2.1 从零解释

#### 计算机语言是什么？
计算机只能理解 0 和 1（机器码）。人类不可能天天写 0101，于是发明了「编程语言」——一种人类能读懂的文本，通过「编译器」或「解释器」翻译成机器码。

#### JavaScript 是什么？
JavaScript（简称 JS）是 1995 年诞生的一门语言，最初只能在浏览器里跑，用来让网页动起来。后来有人把它搬到了服务器上（Node.js），从此 JS 可以写任何程序了。

**JS 的特点**：
- 解释型（不用编译，写完就能跑）
- 动态类型（变量不用声明类型，`let x = 1` 和 `let x = "hello"` 都行）
- 事件驱动（很适合处理"等用户输入 → 响应"这种场景）

#### TypeScript 是什么？
TypeScript（简称 TS）是微软在 2012 年推出的 JS **超集**。意思是：所有 JS 代码都是合法的 TS 代码，但 TS 额外加了 **类型系统**。

打个比方：
```
JS:   let name = "小明"    // 你不知道 name 是什么类型
TS:   let name: string = "小明"  // 明确告诉你这是字符串
```

加了类型后，编辑器能提前发现错误（比如把数字传给了需要字符串的函数），而不是等到运行时才崩溃。对于大型项目（比如这个 2300+ 文件的代码库），类型系统是救命稻草。

#### .ts 和 .tsx 的区别？

| 扩展名 | 全称 | 说明 |
|--------|------|------|
| `.ts` | TypeScript | 纯逻辑代码：函数、类、数据处理 |
| `.tsx` | TypeScript + JSX | 逻辑 + UI 界面代码。JSX 是一种在代码里写 HTML 标签的写法 |

> **备注：JSX 中的 "X" 是什么？**
>
> JSX = JavaScript + **X**ML。XML 是一种和 HTML 很像的标记语言（标签必须闭合、属性必须引号包裹）。React 团队选择用 XML 语法来描述 UI 界面，所以这个 "X" 代表的就是"类 HTML 标签语法"。
>
> ```tsx
> // 你看到的（JSX 写法）：
> <Text color="green">Hello</Text>
>
> // 实际编译后（普通 JS 函数调用）：
> React.createElement(Text, { color: "green" }, "Hello")
> ```
>
> 总结：**X = 允许在 JS/TS 文件里直接写 XML 标签**。不是指某个特定语言，就是一种"代码里嵌标签"的扩展标记。

本项目：
- `src/query.ts` → 纯逻辑，处理 AI 对话循环
- `src/screens/REPL.tsx` → UI 代码，渲染终端界面

### 2.2 TS/JS 核心概念速览

> 以下为常用概念简介，便于快速建立印象。
> **完整语法教程请参阅 [00_01_TS语法教程.md](./00_01_TS语法教程.md)**，按 C 语言教材路径，逐知识点对照式详解（关键字→类型→运算符→控制流→函数→对象→数组→泛型→异步→生成器→模块→错误处理）。

#### ① 变量
```typescript
let count = 0        // 可变变量
const name = "Claude" // 常量
```

#### ② 函数（箭头函数）
```typescript
const add = (a: number, b: number): number => a + b
```

#### ③ 对象和类型
```typescript
interface User { name: string; age: number; email?: string }
type Status = "pending" | "done"
```

#### ④ 数组
```typescript
const nums: number[] = [1, 2, 3]
nums.map(n => n * 2)     // [2,4,6]
nums.filter(n => n > 1)  // [2,3]
```

#### ⑤ 泛型
```typescript
function first<T>(arr: T[]): T | undefined { return arr[0] }
```

#### ⑥ 异步 (async/await)
```typescript
const data = await fetch("/api/user")   // "等"而不阻塞
```

#### ⑦ 生成器 (yield) — 本项目核心
```typescript
async function* stream() { yield "你好"; yield "世界" }
for await (const chunk of stream()) console.log(chunk)  // AI 逐字输出原理
```

#### ⑧ 模块
```typescript
import { doSomething } from './utils.js'  // 类似 C 的 #include
export const config = { port: 3000 }
```

#### ⑨ 解构
```typescript
const { name, age } = user   // 等价于 user.name, user.age
```


## 三、项目运行环境：Bun

### 什么是 Bun？
Bun 是一个 JS/TS **运行时**，类似于 Node.js，但更快。它由 Zig 语言编写，内置了打包器、测试器、包管理器。

本项目选择 Bun 的原因：
1. 原生支持 TypeScript（Node.js 需要额外配置）
2. 启动快（CLI 工具对启动速度敏感）
3. 内置 `bun:bundle` 可以做**死代码消除**（后面会讲）

### 你需要知道的
```bash
bun ./src/entrypoints/cli.tsx   # 运行一个 TS 文件
bun install                      # 安装依赖（类似 npm install）
```

## 四、本项目特殊技术

### 4.1 React + Ink = 终端 UI

React 本身是做网页 UI 的，但 **Ink** 这个库把它搬到了终端：

```tsx
// 这段代码在终端渲染出带颜色的文字
<Box flexDirection="column">
  <Text color="green">Hello, Claude!</Text>
  <Text color="yellow">How can I help you?</Text>
</Box>
```

`.tsx` 文件就是在写这种「终端 UI 组件」。

### 4.2 动态 Import（按需加载）

```typescript
// 不是 import { huge } from './huge.js' 在顶部全部加载
// 而是用到时才加载
if (args[0] === '--version') {
  console.log('v0.3.2')    // 零模块加载，极快
} else {
  const { main } = await import('./main.js')  // 这时才加载完整 CLI
}
```

### 4.3 Feature Flag + 死代码消除（DCE）

```typescript
// feature() 是 bun:bundle 提供的宏
// 构建时如果 feature('KAIROS') 为 false，大括号里的代码会被直接删除
if (feature('KAIROS')) {
  // 外部用户的构建产物中，这段代码不存在
  const assistant = require('./assistant/index.js')
}
```

## 六、本项目中常见的 TS 模式速查

| 语法 | 含义 | 示例 |
|------|------|------|
| `?:` | 可选属性 | `email?: string` |
| `\` | 联合类型 (或) | `string \| number` |
| `&` | 交叉类型 (且) | `A & B` |
| `<>` | 泛型 | `Array<string>` |
| `as` | 类型断言 | `value as string` |
| `??` | 空值合并 | `a ?? b` (a 为 null/undefined 时用 b) |
| `?.` | 可选链 | `user?.name` (user 为 null 时不报错) |
| `!` | 非空断言 | `value!` (告诉编译器 value 一定不为空) |
| `...` | 展开运算符 | `{ ...obj, newKey: 1 }` |
| `for await` | 异步迭代 | `for await (const x of generator)` |
