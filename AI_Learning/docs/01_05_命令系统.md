### 命令结构
```typescript
interface Command {
  name: string                          // 命令名 (无 /)
  description: string                   // 一行描述
  isHidden?: boolean                    // 是否在帮助中隐藏
  inProgressFeedback?: boolean          // 是否显示进度
  options?: CommandOption[]             // 参数定义
  handler(args, context): Promise<void> // 执行函数
  tags?: string[]                       // 分类标签
}
```

### 命令生命周期
- `notifyCommandLifecycle(uuid, 'started')` → 命令开始
- `notifyCommandLifecycle(uuid, 'completed')` → 命令完成
- 用于追踪和日志

## 二、核心命令详解

### `/compact` — 手动压缩上下文
- 触发 `buildPostCompactMessages()`
- 生成摘要，释放 token 空间
- 不影响对话连续性

### `/clear` — 清除上下文
- 重置对话历史
- 重新生成 session ID
- 保留 settings 和 cost 状态

### `/model` — 模型切换
- 弹出交互式选择器 (`ModelPicker`)
- 支持别名 (sonnet/opus/haiku)
- 验证模型可用性
- 实时切换，无需重启

### `/config` — 配置管理
- 读取/修改 settings.json
- 支持全局/项目/本地三个层级
- 实时生效

### `/review` / `/ultrareview` — 代码审查
- 分析 git diff
- 生成审查报告
- ultrareview 提供更深入的分析

### `/init` — 项目初始化
- 创建 CLAUDE.md
- 分析项目结构
- 设置初始配置

### `/commit` / `/commit-push-pr` — 一键提交流程
- 查看 git 变更
- 生成 commit message
- 可选 push + create PR

### `/mcp` — MCP 服务器管理
- 列出/添加/移除 MCP 服务器
- 管理服务器认证

## 三、命令执行流程

```
用户输入 "/commandName args"
  ↓
isSlashCommand(text) → 检测是否为命令
  ↓
getCommandsByMaxPriority() → 匹配命令
  ↓
command.handler(args, context)
  ↓
notifyCommandLifecycle() → 生命周期通知
```

## 四、Feature Flag 控制

许多命令通过 `feature()` 条件加载，外部构建自动剔除：

```typescript
// Ant-only 命令
proactive → feature('PROACTIVE') || feature('KAIROS')
brief     → feature('KAIROS') || feature('KAIROS_BRIEF')
assistant → feature('KAIROS')
bridge    → feature('BRIDGE_MODE')
```

## 五、斜杠命令与工具的关联

某些斜杠命令也会注册为 **工具** (通过 `getSlashCommandToolSkills()`)：
- 命令 `/review` → 模型可通过 Tool 调用 review
- 命令 `/commit` → 模型可通过 Tool 调用 commit
- 实现命令和 Agent 工具的统一接口

## 六、命令子目录结构

每个命令通常组织为：
```
commands/<name>/
  ├── index.ts         → 命令定义 + handler
  ├── <name>.tsx       → React 组件 (交互式命令)
  └── utils.ts         → 辅助函数
```

简单命令则直接为 `commands/<name>.ts`。
