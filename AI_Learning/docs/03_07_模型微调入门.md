# 03_07 — 大模型微调入门

> 面向 Agent 开发者，理解微调"是什么、什么时候需要、怎么做"。

---

## 一、为什么不直接用 API？

### 用 API (推荐起步)

```
优点: 零运维、永远用最新模型、按量付费
缺点: 贵（大量调用时）、有限制（速率/内容审核）、不可定制
```

### 微调自有模型

```
优点: 便宜（大批量推理）、可控（离线部署）、定制化
缺点: 要 GPU、要数据、要维护、效果天花板受基模型限制
```

### 什么时候该微调？

```
✅ 需要微调:
  - 每天调用量极大（>10万次），API 成本太高
  - 需要离线/私有化部署（金融/军工）
  - 需要模型学会特定格式/风格（如特定 JSON 格式输出）
  - 需要模型掌握私有领域知识（但通常 RAG 更经济）

❌ 不需要微调:
  - 调用量小 → API 更划算
  - 想让模型"变聪明" → 微调做不到，这是基模型能力决定的
  - 想让模型知道新的公开知识 → RAG 更合适
```

## 二、微调方法对比

| 方法 | 全称 | 原理 | 成本 | 效果 |
|------|------|------|------|------|
| **SFT** | 监督微调 | 用标注数据训练全量参数 | 极高 | 最好 |
| **LoRA** | 低秩适配 | 只训练少量附加参数 | 低（单卡）| 接近 SFT |
| **QLoRA** | 量化 LoRA | LoRA + 4bit 量化 | 极低（消费级卡）| 稍弱于 LoRA |
| **RLHF** | 人类反馈强化学习 | 用人类偏好训练奖励模型 | 极高 | 对齐人类偏好 |

**Agent 开发者最常用: LoRA / QLoRA** — 消费级 GPU 就能跑。

## 三、LoRA 微调流程

### 第 1 步：准备数据

```jsonl
// 数据格式：指令-回答对
{"instruction": "把以下 Python 代码转成 TypeScript", "input": "def hello():\n    print('hi')", "output": "function hello(): void {\n  console.log('hi')\n}"}
{"instruction": "给以下代码加类型注解", "input": "function add(a, b) { return a + b }", "output": "function add(a: number, b: number): number {\n  return a + b\n}"}
```

**数据量**: 至少要 100-1000 条高质量样本。质量 > 数量。

### 第 2 步：选择基模型

```
常见选择:
  - Llama 3.1 8B (Meta) — 开源标杆
  - Qwen 2.5 7B (阿里) — 中文最佳
  - Mistral 7B — 轻量高效
  - DeepSeek-V3-Lite
  
选型标准:
  - 和你的任务匹配度
  - 显存要求（7B 模型 QLoRA 约需 6-8GB 显存）
  - 许可证（商用是否免费）
```

### 第 3 步：用 LLaMA-Factory 微调（最简单）

```bash
# 安装
git clone https://github.com/hiyouga/LLaMA-Factory.git
cd LLaMA-Factory
pip install -e .

# 准备数据文件 data/my_data.json
# 配置 Web UI
llamafactory-cli webui

# 在 Web UI 中：
# 1. 选择基模型 (如 Qwen2.5-7B)
# 2. 选择微调方法 (LoRA)
# 3. 上传数据集
# 4. 设置参数（rank=8, lr=2e-4, epochs=3）
# 5. 点击"开始训练"
```

### 第 4 步：评估

```python
# 用测试集对比微调前后的效果
test_cases = [
    ("Python 转 TS: def foo(): pass", "function foo(): void {}"),
    # ... 20-50 个测试样例
]

for input_text, expected in test_cases:
    base_output = base_model.generate(input_text)
    finetuned_output = finetuned_model.generate(input_text)
    
    base_score = similarity(base_output, expected)
    ft_score = similarity(finetuned_output, expected)
    
    print(f"基模型: {base_score:.2f} | 微调后: {ft_score:.2f}")
```

### 第 5 步：合并 + 部署

```bash
# 合并 LoRA 权重到基模型
llamafactory-cli export \
  --model_name_or_path Qwen/Qwen2.5-7B \
  --adapter_name_or_path ./saves/my_lora \
  --export_dir ./my_model_merged

# 部署（见 03_08）
```

## 四、数据准备要点

### 质量原则

```
1. 多样性: 覆盖各种场景，不要全是同一类问题
2. 准确性: 标注的 output 必须正确（错误的标注比不标注更糟）
3. 一致性: 格式统一，同样的输入期待同样的输出风格
4. 去噪: 删除低质量、模糊、矛盾的样本
```

### 数据量经验值

| 场景 | 最少 | 推荐 |
|------|------|------|
| 格式/风格微调 | 100-500 | 1000 |
| 任务微调 | 500-2000 | 5000 |
| 领域知识注入 | RAG 更合适 | — |

## 五、关键认知

1. **微调不"增加知识"** — 微调主要改变模型的行为模式（格式/风格/指令遵循），不是注入新知识。知识用 RAG。
2. **数据质量 >> 数量** — 100 条高质量数据 > 10000 条垃圾数据
3. **基模型决定上限** — 7B 模型微调后也不会比 70B 强
4. **微调有遗忘风险** — 学了一个新任务，可能忘了之前的能力
5. **先试 Prompt/RAG** — 90% 的场景不需要微调
