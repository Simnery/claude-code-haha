## 二、核心数据流

### 用户输入 → 模型响应 → 工具执行 → 最终回复

```
用户输入
  ↓
[1] processUserInput()
  解析命令 / @mention / 附件 / CLAUDE.md / memory
  → Message[]
  ↓
[2] query() / QueryEngine.submitMessage()
  ├─ 构建 system prompt + user context
  ├─ 压缩层 (snip → micro → collapse → auto)
  └─ while(true) 循环
      ↓
[3] API 调用 (callModel)
  model: ANTHROPIC_MODEL 或 --model 指定的模型
  baseURL: ANTHROPIC_BASE_URL (可指向 LiteLLM 代理)
  → SSE Streaming → yield 每个 token
  ↓
[4] 响应后处理
  ├─ max_output_tokens 恢复
  ├─ reactive compact
  ├─ fallback 重试
  └─ stop hooks
  ↓
[5] 工具执行 (runTools)
  ├─ 权限检查 (canUseTool)
  ├─ tool.execute()
  └─ 结果注入为 tool_result
  ↓
[6] 循环判断
  ├─ 有 tool_use → 回到 [2] 继续
  └─ 无 tool_use → 返回终端状态
```

## 四、关键设计决策

### 1. 动态 Import + Feature Flag 做 DCE
```
feature('KAIROS') ? require('./assistant/...') : null
```
构建时 `bun:bundle` 剔除未使用的代码块，减小外部构建体积。

### 2. Bootstrap 隔离
`bootstrap/state.ts` 不 import 任何项目模块，作为全局状态单例，避免循环依赖。

### 3. 生成器模式 (AsyncGenerator)
`query()` 使用 `async function*` 流式 yield 消息，上层 (REPL/SDK) 通过 `for await` 消费，天然支持中断和背压。

### 4. 依赖注入 (`query/deps.ts`)
核心循环依赖通过参数注入，测试时可 mock `callModel`、`autocompact` 等。

### 5. 多 Provider 抽象
通过 `ANTHROPIC_BASE_URL` + `modelStrings.ts` 实现多 AI 提供商支持，无需修改核心代码。

## 七、会话生命周期

```
启动
  ├─ cli.tsx fast-path → 或 → main.tsx
  ├─ init() 配置/认证/遥测初始化
  ├─ launchRepl() Ink TUI 渲染
  │
循环 ───
  ├─ 用户输入 → query()
  ├─ API 流式响应 (ink 实时渲染)
  ├─ 工具调用 → 权限 → 执行
  ├─ 上下文压缩 (自动/手动)
  │
  ├─ /model → 切换模型 (无需重启)
  ├─ /clear → 重置对话 (保留配置)
  ├─ /compact → 手动压缩上下文
  │
退出
  ├─ /exit 或 Ctrl+D
  ├─ gracefulShutdown() 清理
  ├─ 写入 transcript JSONL
  └─ 下次可用 --continue / --resume 恢复
```
