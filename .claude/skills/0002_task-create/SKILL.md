# 开发任务创建 Skill

**格式规则**：Skill 是模板，禁止出现具体任务 ID、文件路径、数量。统一用占位符：`{任务ID}` `{已完成}` `{总计}` `{X}%`。

---

## 调用时机

### 主动触发（必须提示用户）

发现以下情况时，**主动询问用户**是否创建任务记录：

| 信号 | 示例 |
|------|------|
| 3 个及以上独立步骤 | "先改 A 模块，再调 B 接口，最后加测试" |
| 涉及多个文件/目录操作 | "重构 XX 模块"、"给所有组件加错误处理" |
| 预计跨会话才能完成 | "排查这个 bug"（需多轮调试） |
| 用户明确说要做"功能/修复/重构/任务" | "实现 XX 功能"、"修复 XX bug" |

**提示模板**：
> 这个操作涉及多个步骤（预估 N 步），当前没有任务追踪文档。是否先创建一个任务记录？防止窗口中断丢失进度。

### 被动触发（用户直接要求）

用户明确要求"创建任务"、"新建任务"、"记录任务"时直接执行创建流程。

## 执行流程

### 0. 环境初始化（首次执行时）
检查 `.claude/settings.local.json` 是否存在：
- 若**不存在** → 创建文件，写入空权限配置：
  ```json
  {
    "permissions": {
      "allow": []
    }
  }
  ```
- 确认 `.gitignore` 包含 `.claude/settings.local.json`

### 1. 确定任务信息
- **任务标题**：简要描述任务目标
- **类别**：bugfix / feature / refactor / docs / release / chore
- **创建时间**：当前日期

### 2. 创建任务文件

**文件结构**（.md 文件必须放在同名文件夹**内部**）：

```
00_local_task/tasks/{日期}_{类别}_{简要描述}/
  └── {日期}_{类别}_{简要描述}.md       ← 任务主文件（唯一入口）
```

- 步骤1：在 `00_local_task/tasks/` 下创建文件夹（项目根目录，不在 `.claude/` 内，无权限弹窗）
- 步骤2：在文件夹内部创建 .md 文件
- 命名规则：文件夹名与 .md 文件名相同（即 `{任务ID}`）
- 此目录已配置 .gitignore 排除

**任务文档模板**：

```markdown
# {任务标题}

> **创建时间**: {日期}
> **类别**: {类别}
> **状态**: active
> **更新时间**: {日期}

## TL;DR
任务刚创建，待执行。

## 进度表
| # | 步骤 | 状态 | 备注 |
|---|------|------|------|
| 1 | {步骤1} | ⏳ | |
| 2 | {步骤2} | ⬜ | |
| 3 | {步骤3} | ⬜ | |

## 当前操作
- [ ] {步骤1 的具体 checklist}

## 已完成操作
（暂无）

## 遇到的问题
| 时间 | 问题 | 状态 |
|------|------|------|

## 进度日志
| 时间 | 步骤 | 操作 | 结果 | 下一步 |
|------|------|------|------|--------|
| {时间} | 初始化 | 创建任务文档 | 任务框架就绪 | {步骤1} |
```

### 3. 更新任务索引
- 检查 `00_local_task/task_index.md` 是否存在，不存在则创建
- 新建 → `active` / 暂停 → `paused` / 完成 → `done`
- 字段：`id | status | owner | last_update | task_file`

### 4. 任务进行中持续更新

**强制规则**：每完成一个子步骤后，**先更新文档，再继续下一步**。不更新不往下走。

固定更新位置（按顺序修改以下 6 处）：

| # | 位置 | 操作 |
|---|------|------|
| 1 | `> **更新时间**` (文件头部) | 刷新为当前时间 |
| 2 | `## TL;DR` | 一句话概括当前状态 |
| 3 | `## 进度表` | 对应步骤行 → `✅`，下一行 → `⏳` |
| 4 | `## 当前操作` | 更新为下一步的 checklist |
| 5 | `## 已完成操作` | 追加刚才完成的事项 |
| 6 | `## 进度日志` | **追加一行**：时间 \| 步骤 \| 操作 \| 结果 \| 下一步 |

**自检**：任务进行中，若发现进度日志最新行与 TL;DR/进度表 不一致 → 立即同步后再继续。

**批量操作**：每完成一个子步骤就完整走一遍 6 处更新，不允许攒到最后一次更新。

### 5. 长任务防精度衰减（检查点 + 预算监控）

**问题**：上下文快满时，模型精度下降，容易遗漏步骤或偏离方案。

#### 5.1 检查点机制

每完成一个里程碑（或每 N 个子步骤），在 `## 进度日志` 中写一条 `[检查点]` 条目：

```
| 时间 | 步骤 | 操作 | 结果 | 下一步 |
|------|------|------|------|--------|
| 23:00 | [检查点] 第1阶段完成 | {已完成}/{总计} 步骤，进度 {X}% | 全部自检通过 | 下一阶段入口 |
```

检查点内容：
- 已完成多少
- 当前进度百分比
- 关键决策/变更（如有）
- 下一步精确入口

#### 5.2 上下文预算监控

当出现以下信号时，**立即写检查点，提示用户执行 `/clear`**：
- 对话轮次明显增多，响应变慢
- 需要频繁回顾前文才能记得当前状态
- 已连续处理超过 10 个子步骤

**提醒模板**：
> 检查点已写入。建议 `/clear` 清理上下文后，发送以下命令恢复：
>
> ```
> 继续 {任务ID}
> ```

**禁止行为**：必须用上述模板做**陈述句提示**。禁止出现以下问句形式：
- ❌ "是否现在启动检查，还是先 /clear？"
- ❌ "要继续还是暂停？"
- ❌ "需要 /clear 吗？"

#### 5.3 `/clear` 后恢复协议

执行 `/clear` 后，**只需一句话恢复**：

```
继续 {任务ID}
```

AI 收到此命令后的标准动作：
1. 定位任务文件 `00_local_task/tasks/{任务ID}/{任务ID}.md`
2. 读任务文档 `## TL;DR` → 了解当前状态
3. 读 `## 当前操作` → 确定下一步
4. 读 `## 进度日志` 最新 3 行 → 确认最后进度
5. 立即继续执行，不追问、不翻旧对话

### 6. 任务收尾沉淀（done 前强制）
- **自检清单**：相关测试通过？覆盖到改动行？质量门通过？
- **验证**：根据改动面运行对应检查（参考 AGENTS.md 验证路由表）
- **知识沉淀**：是否有值得记录的踩坑经验
- **索引更新**：状态改为 done
